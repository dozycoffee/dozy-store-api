# ADR-0007: 카테고리는 메뉴에 담지 않고 채널이 Catalog의 공개 카테고리 목록을 직접 받는다

- **상태**: 채택
- **날짜**: 2026-10-15
- **관련**: 이슈 #46, [요구사항](../requirements.md) 5.1, 5.2, 7.1, [시나리오](../scenarios.md) S4, S8, [API](../api/public.md), [ADR-0004](0004-public-customer-menu-for-all-channels.md)(일부 대체), dozy-catalog-api 이슈 #147(공개 카테고리 목록), #135(카테고리 노출 순서)

## 맥락

ADR-0004는 손님 메뉴를 채널과 관계없이 로그인 없는 공개 리소스 하나로 만들기로 했고, 메뉴에 카테고리 구조(대분류·소분류와 본사가 정한 노출 순서)를 함께 담도록 설계했다. 점주가 쓰는 매니저 화면도 카테고리 이름을 Store가 붙여 주도록 했다. 이를 위해 Store는 Catalog의 카테고리 목록을 서비스 계정으로 받아 캐시해야 했다.

하지만 카테고리는 매장과 무관하다. 모든 매장과 채널에서 같은 트리이고 노출 순서도 같다. Store의 판단(노출, 품절, 판매 범위)에 쓰이지 않고, Store는 받아서 전달만 한다. 그 사이에 Store를 두면 카테고리 응답이 바뀔 때 Store 변경과 배포가 함께 필요하고, 순서 변경이 Store 캐시 시간만큼 늦게 반영된다. Catalog는 카테고리 목록을 인증 없이 읽을 수 있는 공개 경로(`GET /api/v1/public/categories`)로 제공하기로 했다(dozy-catalog-api #147).

## 결정

- **메뉴와 매니저 상품 목록에 카테고리의 이름·구조·노출 순서를 담지 않는다.** 상품마다 카테고리 ID(Catalog 상품 기준 정보의 값)만 담는다.
- 채널(손님 앱·웹·키오스크·POS, 점주 화면)이 Catalog의 공개 카테고리 목록을 직접 받아 카테고리 탭을 만들고, 상품을 카테고리 ID로 묶는다. 탭의 순서는 본사가 정한 노출 순서다.
- Store는 카테고리 목록을 Catalog에서 받지 않고 캐시하지 않는다(`GetCategoriesUseCase`, 카테고리 목록 캐시, Catalog 호출 표의 카테고리 목록 행이 없어진다).
- 메뉴의 상품이 채널이 받아 둔 카테고리 목록에 없는 카테고리 ID를 가질 수 있다(Catalog 공개 목록이 최대 몇 분 캐시된다). 처리는 채널이 정한다(목록을 다시 받는 등).
- 상품에 대해 메뉴를 한 곳에서 만들어 모든 채널이 같게 본다는 ADR-0004의 원칙은 그대로다.

## 검토한 대안

- **Store가 카테고리를 메뉴에 담아 전달한다**(ADR-0004의 설계): 채널이 메뉴 하나만 받으면 되고 메뉴에 있는 상품의 카테고리만 내려 준다. 하지만 Store가 판단에 쓰지 않는 값을 받아 캐시하고 전달해야 하고, 카테고리 변경이 Store 캐시 시간만큼 늦게 반영되며, Catalog에 Store용 카테고리 내부 API를 두어야 한다.
- **채널이 카테고리 순서를 자체 설정으로 정한다**: Catalog에 카테고리 노출 순서가 필요 없다. 하지만 카테고리 구성을 바꿀 때마다 채널을 배포해야 하고 채널 사이의 순서가 달라질 수 있다. 본사가 한곳에서 정하는 쪽을 택했다(dozy-catalog-api #135).
- **채널 앞에 BFF를 두어 합친다**: 채널은 호출 하나로 끝난다. 하지만 손님 채널용 BFF를 새로 만들어야 한다.

## 결과

- **얻는 것**
  - Store가 카테고리를 다루지 않아 응답과 연동 계약이 작아진다. 카테고리 변경에 Store 변경이 필요 없다.
  - 카테고리 순서 변경이 Catalog의 캐시 시간(공개 응답 캐시)만 지나면 모든 채널에 반영된다.
  - Catalog에 Store용 카테고리 내부 API가 필요 없어진다.
- **감수하는 것**
  - 채널이 두 곳(Catalog의 카테고리 목록, Store의 메뉴)을 받아 합쳐야 한다. 이 상품이 속한 카테고리와 목록이 어긋나는 경우를 채널이 처리한다.
  - 이 매장 메뉴에 상품이 없는 카테고리도 Catalog 목록에는 있으므로 빈 탭을 채널이 거른다.
  - Catalog의 공개 카테고리 목록이 채널의 메뉴 표시에 필요한 의존이 된다.
- **후속 작업**
  - Catalog 쪽: 공개 카테고리 목록 API(dozy-catalog-api #147)와, Store용 조회 API 이슈(#136)에서 카테고리 목록 항목 삭제
